# Changelog

All notable changes to `@open-loop/engine`. The 0.1.0 entry is hand-curated to describe what the initial release **is**; from 0.1.1 onward, entries are generated by `release-it` from conventional commits.

## 0.1.0 — _Unreleased_

Initial public release. A headless TypeScript substrate for incremental and idle games — reactive state, big-number math, a composable evaluation kernel, and registration surfaces for the patterns idle games keep re-inventing.

### What's in it

- **Five-layer architecture** — `primitives` → `core` → `systems` → consumer modules, with `harness` alongside as an optional balance-sim layer; strict one-way deps. The `primitives` layer has zero dependencies and is Vue-free; `core` adds reactivity; `systems` adds registration surfaces over core; consumers compose on top. Game modules never import `harness` — balance tooling does.

- **Reactive resources** — `createResource()` produces Vue-reactive game quantities backed by `break_eternity.js` `Decimal` arithmetic. Helpers cover the common path: `addResource`, `subtractResource` (with insufficient-funds check), `hasResource`, `resetResource`, `displayResource`. Persistent resources expose `best` (high-water mark) and `cumulative` (lifetime gain) refs.

- **Evaluation kernel** — Pure-function evaluation separated from reactive state, so the same kernel runs in a browser or a headless sim. Includes:
  - **Modifier chains** — composable additive / multiplicative / replacement bindings with named registries.
  - **Formulas** — closed-form rate / cost / scaling functions over `Decimal`, with pacing helpers.
  - **Requirements** — cost, boolean, and predicate gates.
  - **Conditions, effects, gates** — declarative data structures usable in JSON, mods, and saves.
  - **Computed bindings** and **trace** for debugging chain evaluation.

- **Persistence and save** — Auto-derived save schemas from persistent-ref `DefaultValue`s via `zod`. Compression via `lz-string`. Load-time validation catches "field renamed mid-dev-cycle" save corruption without hand-written schemas. `SaveManager` orchestrates encode / decode / migrate / peek.

- **Game loop** — `createTickDriver()` ticks registered handlers with `dt` in seconds. Offline catch-up via `offline.ts`. Throttling, profiling, and stasis-mode for headless determinism.

- **Category systems** — Typed batch-registration surfaces for the validated incremental-game patterns: skills, producers, purchasables, achievements, challenges, dialog, subjects, zones. Each category exposes `register` / `getDef` / `getInstance` / `patch` (for mods) and self-enrols into a global content registry that consumer tooling can walk without install-time coupling.

- **Cycle / sequencer / time** — `createCycle`, `createSequencer` (with fill strategies), `createTimeSystem`, `createReset`, `createRetentionPolicy`. Reusable composition primitives for time-stepped and progression-based games.

- **Spatial primitives** — `core/spatial/graph` and `core/spatial/grid` for games that need adjacency without committing to a UI.

- **Headless simulation** — `runHeadless` and `createRunPool` (in `core`) drive an engine to completion without a browser; the `harness` layer builds on them with `runMatrix`, `runMatrixUntil`, `runSensitivity`, `runBatch`, plus walker / picker / probe / solver primitives for balance sweeps. Same engine logic runs headless or in a browser.

- **Module system** — `createEngine({ gameId })` returns a host that consumers extend via `engine.use({ id, install(ctx) { ... } })`. Install context exposes `onTick`, `onSave`, `onLoad`, `onReset`, plus dependency injection over engine registries.

### Entry points

- `@open-loop/engine` — full surface (most consumers start here).
- `@open-loop/engine/primitives` — Decimal, RNG, types only. Zero Vue dependency.
- `@open-loop/engine/core` — reactive primitives without category systems.
- `@open-loop/engine/systems` — category surfaces alone.
- `@open-loop/engine/harness` — balance-sim tooling over a built engine (matrix sweeps, sensitivity, perturbation, probes, solver). `runHeadless` / `createRunPool` live in `core`, not here.
- `@open-loop/engine/types` — evaluation-kernel interface types only (`IResource`, `ICondition`, `IEffect`, `Analyzer`, …); not the factory return types (`Engine`, `Resource`, …).

### Stability

Pre-1.0. Expect breaking changes between minor versions until 1.0. The version bump for `feat!:` / `BREAKING CHANGE:` commits is **MINOR** (not MAJOR) while in 0.x — breaking changes are expected here. Pin `~0.1.0` if you need patch-only stability for a jam or short project.

Contract changes made before this release was cut, recorded here because
`release-it` generates from commits only from 0.1.1 onward:

- **Sequencer `skip` ordering.** A list-mode sequencer now advances `cursor` past
  the skipped item *before* emitting `skip`, matching queue mode (which already
  popped first) and every other emit site in the primitive. A listener that read
  `cursor` as pointing at the skipped item reads `cursor - 1`.

### Requirements

- Node ≥ 18, ESM-only (no CommonJS export). Published JS and types carry explicit `.js` extensions, so plain node ESM works — no bundler required at runtime.
- Bundler-mode TypeScript resolution (Vite, Webpack, ESBuild). `moduleResolution: "nodenext"` currently fails on `break_eternity.js`'s typings (upstream CJS-interop issue) — see the README install notes.
- Peer dependencies: `vue ^3.4`, `break_eternity.js ^2.1`, `eternal_notations ^1.1`. Optional: `ts-morph` (only needed to run the bundled `ol-domain-map` generator).
