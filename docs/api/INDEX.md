## Tier map

Per-tier landing pages in dependency-ascending order — numeric foundation first, headless harness last. This is *not* the L1→L4 consumer-journey ordering from `../consumer-guide.md` § The expression spectrum (helpers → categories → raw → declarative); see the by-abstraction-level lens below for that cut.

- `resources.md` — Numeric foundation and the named-quantity factory. `Decimal` arithmetic, formatting, randomness, and notations sit underneath `createResource`, which produces the reactive game values everything else reads. Conversion and resource bags layer on top. Start here when modelling a new countable quantity.
- `mechanics.md` — The composable evaluation kernel. Modifier chains, requirements, formulas, computed bindings, conditions, effects, gates, and trace. Pure-function evaluation (no Vue dependency in the core) plus reactive wrappers — the substrate the content systems compose against.
- `composition.md` — Substrate the content systems compose against. `CategoryBase` + `ContentRegistry` + `Feature` form the meta-shape every batch-registration category extends; `Sequencer` (with fill strategies) is the reusable composition primitive used by both engine and content layers. Start here when building a new category factory or composing a custom registration surface.
- `content-systems.md` — Currency-flow and long-arc structure systems — the validated incremental-game primitives. Purchasable / Producer / Achievement / Inventory / BestOf for economy; Skill / Loop / Challenge / Zone / Slot / AutomationTiers / LoopLog for progression. Each is a typed registration surface over the mechanics kernel; category factories batch-register many definitions.
- `content-narrative.md` — Tier-4 character-interaction systems — specialized in incremental games, near-default in narrative-adjacent codebases. Dialog (authored conversation graphs + native runtime + swappable adapter contract) and Relationship (five typed sub-primitives: scalar / faction / tiered / vector / flag). Both compose engine substrate (conditions, effects, gates) into save-friendly drivers.
- `lifecycle.md` — Save/load, reset cascades, persistent refs, offline catch-up, retention policies. Anything that crosses session boundaries or prestige resets. `withPersistentContext` is the namespacing primitive every save-touching factory uses; `createSaveManager` is the multi-slot envelope; `createReset` carries retention rules between prestige tiers.
- `runtime.md` — The runtime substrate every engine carries. `createEngine` and the module/event/save wiring; the game loop (variable-dt and fixed-step modes); typed per-instance event emitter; throttle, time tracking, transition-distance math; the ambient game-state-accessor context. Start here to understand how an engine assembles and ticks.
- `introspection.md` — The cross-cutting "walk every X" surface external tools read — balance workbenches, sim pickers, devtools panels, mods. `EngineCategories` plus the per-engine registries (chain / resource / effect-system), the `OverrideRegistry` + `TuningRegistry` + `tunable()` pattern that exposes designer-flagged knobs, and the Profiler + Safeguards instrumentation. All discoverable via injection keys with no install-time coupling.
- `advisors.md` — Decision-support systems that observe the engine and rank or recommend actions. The rule advisor + evaluator (rank candidates against a rule set), goal picker (which goal to pursue next), recommendation system (curated next-actions for the player), and the selection policies they share.
- `spatial.md` — Coordinate-based primitives. Grid, graph, scope stack, influence layer. Used by board-state and adjacency-driven games — hex maps, dungeon layouts, factory grids. Headless: no rendering, just adjacency and traversal.
- `harness.md` — Headless-sim substrate. Matrix and predicate-bounded runners, probes, content walkers, the picker for solver/UI enumeration, solvers (bisection), perturbation, analyzers, run pools, and typed harness contracts. Separable from the rest of the engine — game code never imports harness; balance tooling does.

## Reserved names

A few symbols share a stem and are easy to confuse. Each links to its anchor:

- **GameLoop** — engine tick scheduler. `createGameLoop`. → runtime.md#game-loop
- **Loop** — loop-incremental gameplay run (Idle Loops, Cavernous, Loopy Loops). `createLoop`. → content-systems.md#loop
- **LoopLog** — per-loop metric delta recorder; observes a `Loop`'s lifecycle. `createLoopLog`. → content-systems.md#looplog
- **`createReset`** vs **`Loop.thingsToReset`** — `createReset` is the standalone prestige primitive (lifecycle); `Loop` extends `ScopedReset` and carries its own reset list per run.

In prose: "Loop" alone always means the gameplay primitive. Engine substrate is always "GameLoop." Tick-cadence concepts are "tick" or "frame," never "loop."

## Predicate forms

Engine fields that gate behavior accept one of four shapes. Pick the most-specific that fits.

| Form | Shape | Use when | Predictor-friendly | Serializable | Tier anchor |
| --- | --- | --- | --- | --- | --- |
| `Gate` | typed AST (`ResourceGteGate`, `UnlockGate`, …) | category-aware predicate; want `timeUntilGateFlip` + projection to `ICondition` | yes (typed) | yes | mechanics.md#gate |
| `ICondition` | declarative AST over `GameStateAccessor` | save-replay, mod configs, balance sim — predicates resolved by dot-path string IDs | yes (`extractDependencies`) | yes | mechanics.md#conditions |
| `Requirement` | cost-bearing predicate with pay strategy | the predicate also charges a resource (cost, bulk-buy via inversion, pay-by-reset / pay-by-division) | partial | no (closures) | mechanics.md#requirements |
| `Computable<boolean>` | ref / computed / getter | typed refs already in scope; no introspection needed; predicate doesn't fit dot-paths | no | no | mechanics.md#computed |

Fields accepting multiple forms: `ChallengeDef.{visible, canStart, goal}` (`Gate` | `ICondition` | closure), `PurchasableOptions.requirements` (`Requirement[]`), `AchievementOptions.requirement` (`Computable<boolean>` | `Gate`). When a field accepts a `Gate`, prefer it — `Gate` is the only form that gives both flip-distance introspection and category awareness without a `GameStateAccessor` mapping.

## Lenses

The default lens is **by-question** — the task table at the top of this file. Two alternative cuts when that framing doesn't fit:

### By abstraction level

The expression spectrum from `consumer-guide.md`: pick the most specific level that fits, drop down only when the level above is fighting you. Full prose: ../consumer-guide.md#the-expression-spectrum.

- **L1: Resource helpers** — `addResource`, `subtractResource`, `hasResource`, `displayResource`, `Resource.best`, `Resource.cumulative` → resources.md#resource
- **L2: Category systems** — `createSkillCategory`, `createPurchasableCategory`, `createProducerCategory`, `createAchievementCategory`, `createDialogCategory`, `createRelationshipCategory`, … the default for game content → content-systems.md, content-narrative.md
- **L3: Raw primitives** — `createScalingPurchasable`, `createLoop`, `createModifierChain`, `createCategoryBase` → content-systems.md, composition.md, mechanics.md, lifecycle.md
- **L4: Declarative data** — `C` / `E` builders, `ICondition` / `IEffect`, `Gate`. The data-driven escape hatch for save replay, mod configs, balance tools → mechanics.md#conditions, mechanics.md#effects, mechanics.md#gate

### By layer

Engine source layers `primitives → core → systems → harness` with one-way imports. Tier ≠ layer — most tier files mix layers:

- **primitives/** — zero-Vue foundational types and helpers (`Decimal`, `RNG`, `ICondition` / `IEffect` types, `Analyzer` shape).
- **core/** — generic reactive primitives (modifiers, conditions, effects, persistence, save manager, game loop, transitions).
- **systems/** — typed registration surfaces (every category factory; reset / retention; dialog runtime; advisors; gate).
- **harness/** — headless-sim substrate (runners, probes, walkers, picker, perturbation, solvers, run pool).

Open `dist/index.d.ts` after a build for the canonical layer split — `parse-dts.mjs` derives each symbol's layer from its source file.
